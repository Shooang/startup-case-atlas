## 故事正文

Andy Cloke 在伦敦。他大学读工程，不喜欢，毕业后自学编程转行，做过几年自由职业的 JavaScript 和 React 开发。

他有一套找点子的固定框架，说得也很直白：找一个正在暴涨的新平台，去看那些成熟平台上已经跑通的工具，然后把同样的东西搬到新平台上。

他先做的不是 Data Fetcher。最早是 Verbly，一个学西班牙语动词变位的小工具，上了 Hacker News 首页。他说那种"很多人用我在卧室里写的东西"的感觉，让他上瘾。真正赚到钱的是 Influence Grid，一个 TikTok 网红目录，做到 $3K MRR，然后以 $55K 卖给了另一家公司。那是他第一次靠副业拿到真金白银。

Data Fetcher 用的还是那套框架。

他在 Google Sheets 上看到一个插件叫 API Connector，做的是把外部数据拉进表格。而 Airtable——他形容为"加强版的 Google 表格"——刚刚开放第三方应用市场。同类需求，新平台，没人做。

更巧的是，Airtable 的应用用 React 写，正是他最熟的技术。他做自由职业那几年，给创业公司写的就是 JavaScript 和 React——这段经历直接决定了他能一个月把第一版做出来。

他自己也承认，时机是撞上的运气：Airtable 恰好在那时候把应用市场开放给第三方，而这类窗口不会一直开着。

2020 年 8 月开工。一个月写出第一版。他自评"第一版相当糟糕"，但核心功能是通的：能从 API 拉数据进来。

接下来是三个月。不是开发，是审核。Airtable 的应用市场跟手机应用商店一样，提交、排队、等批准，中间不能热更新，出了问题只能重新发版。为了不把老用户弄坏，他每一版都反复测，还提前写了详细的帮助中心，把售后压力压到最低。

还有一个坑：市场本身不收钱。他得自己搭一套订阅和收费，粗糙，但够用，够他拿到第一批付费客户、确认这件事成立。

他反复强调的一个观察是长尾。客户全是 Airtable 用户，但用途散得离谱：有人拉股价和汇率，有人拉加密货币价格，有人拉 Google Analytics 指标；有个客户接的是葡萄园用的 CRM，还有人在导一个缝纫爱好者社区 Ravelry 上的纸样。前后接过 1000 多个不同的应用。

上线一年多，190 个付费客户，$6,500 MRR。他说增长在加速。页面头部现在的数字是 $23K/月。

## 可用观点

- 平台刚开放第三方市场时，是少数"获客免费、竞争为零"的窗口，窗口期通常只有一两年
- 审核周期长反而是壁垒：愿意等三个月的人不多，等过去就挡住了后来者
- 长尾需求不需要事先想清楚，接得够多，用例会自己浮现
