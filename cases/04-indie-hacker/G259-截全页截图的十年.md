## 故事正文

2012 年 11 月 6 日，Peter Coles 首次发布了一个名为 Full Page Screen Capture 的浏览器扩展。十年后，它已有 800 万用户和数万个五星好评，更名为 GoFullPage，迈入第二个十年。

起因是一个很具体的需求。当年他在设计一个大型泡沫板的海报，觉得在网页上排版会很有趣；设计定稿后才发现，他无法把网页保存为像素完美的图像。他试了网页商店里的几款截图扩展，没有一个能正确捕捉整个页面。与其放弃，不如自己写一个。他最初把这个扩展作为解决特定问题的小副项目，并在 GitHub 上开源了。看到安装量上升、收到仓库的问题和 PR 时，他很兴奋。

这个产品看起来简单，实际上正确截取整个网页比看上去复杂得多。浏览器上有很多奇怪的代码，GoFullPage 在捕捉时会分析当前网页的代码，查看页面如何滚动，尝试标准化底层布局规则，以获得一致的截图。Coles 有两条指导原则：第一，所有捕捉技术都必须通用化——不写任何针对特定网站特定标记的代码，代码只识别一般场景、以一般方式解决，这样无论网站如何演变，产品都能继续工作；第二，能完成工作——截图步骤没有专家控制选项，虽然会让想微调的用户沮丧，但长期看避免了产品变得过于复杂和脆弱。

产品的标志性细节里藏着他的性格。因为扩展需要滚动整个页面才能生成截图，他觉得需要一个特别一点的进度条，于是找来了那个"饥饿"进度条；还有一个创业笑话是"你的产品不是真正的产品，直到它有了五彩纸屑功能"——推出高级服务时，他真的给欢迎页面加上了 emoji 烟火。

早期反馈同样塑造了产品。第一个版本里，扩展弹出窗口有一个"开始捕捉"按钮，同事 Georges Duverger 试用后问他：为什么要再点一次按钮？为什么不在激活扩展时就自动开始捕捉？他非常喜欢这个反馈——它帮助确立了让扩展尽可能快速简单的核心理念。

免费模式撑不住时间。随着用户数量大幅增长，保持顺利运行的工作量也在增加，客户支持集成对扩展的有效性至关重要，单是管理它就变得难以应付。他需要一种方式为扩展的持续存在提供资金，于是推出了提供编辑、注释等功能的高级服务——原始的捕捉功能仍然免费。客户支持后来反哺了产品：用户通过支持渠道报告 JavaScript 错误和失败 URL，他和团队花大量精力解答每一个请求，从中获得使用案例、用户体验甚至产品路线图的洞察；他们还引导用户按"你做了什么、期望什么、实际发生了什么"来报告问题。

他对同行的建议朴素：开始公开构建，不断构建——你构建的大多数东西可能对大多数人来说都不有趣，但你在构建中会不断学习。Chrome 应用网店在这个产品的传播中起到了关键作用。

## 可用观点

- 长命产品的技术底座是通用化：不绑定任何网站的特定标记，才能在网页世界十年变迁里始终有效
- 免费截图是获客，付费高级服务是给维护成本发工资——800 万用户的规模本身就是护城河
- 客户支持不是成本中心：每一个错误报告都是无法通过其他渠道获得的产品洞察
