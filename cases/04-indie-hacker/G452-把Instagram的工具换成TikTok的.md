## 故事正文

Andy Cloke 给了一套找产品的方法，四步，他自己用这套方法做出过两个能收钱的产品。

第一步，找一个正在爆发增长的平台。他用一个叫 Exploding Topics 的工具站帮忙看趋势，原理是看谷歌搜索量的增长，用来找那些正在流行或即将成为主流的话题。他自己通常用"商业""创业""技术"这几个词来过滤。

第二步，也是他自己标为最关键的一步：去看更成熟平台上的成功工具。找那种跟现有平台相关、可以被复制、但换到另一个平台还能继续长的工具。

第三步，为新平台做一个等效的工具。构建过程他略过了，只强调一件事：尽快做出来，用来验证想法。

第四步，利润来自缺乏竞争。因为第二步已经刻意挑了低竞争甚至没有竞争的品类，所以会有一段先发优势；会有一批客户需要这个东西却没有别的选择，于是愿意付钱。

他自己给的两个例子，都是这套流程的产物。

第一个是 Data Fetcher。他注意到 Google Sheets 上有一个插件叫 API Connector，用来跑 API 请求。同时他知道 Airtable 是 Google Sheets 的竞争对手，那阵子发展得很快、也很受欢迎。Airtable 刚开放了应用市场，他顺势做出 Data Fetcher——让你在 Airtable 里跑 API 请求。2020 年 12 月，这个产品每月收入 280 美元。到 2022 年 1 月，每月 5000 美元。

第二个是 Influence Grid。2019 年 12 月，他注意到"TikTok"是个热门话题——他的原话是"所有人和他们的奶奶都在 TikTok 上"。他去研究了一下其他市场，发现有几十个"Instagram 网红搜索引擎"。于是他把 Instagram 换成 TikTok，做了一个"TikTok 网红搜索引擎"，帮品牌找 TikTok 网红。这个产品月收益做到 3500 美元，最后以 5 位数的价格卖给了另一家公司。

两个案例的共同点不是勤奋，是顺序：先确认需求已经被别人验证过，再确认这个需求还没被搬到新平台上。他做的从来不是发明一个需求，是把一个被证明过的需求平移到一个供给还没到位的地方，然后赶在别人之前站住。

至于"复制"这件事的道德问题，他没有讨论。他给的理由是商业性的：那个平台上还没有人做，而用户已经在找。

## 可用观点

- 不要发明需求，搬需求：先在成熟平台找到被验证的工具，再问它还能不能在别处再长一次
- 先发优势的本质不是更快，是"用户没得选"
- 新平台开放生态的头几个月，是这类复制品唯一的时间窗口
