## 故事正文

2020 年 12 月 1 日，一个叫 Ryan H 的人在 Indie Hackers 发了一个提问帖。他说自己在考虑做一个 VS Code 插件，然后补了一句前提：大多数 VS Code 插件都是免费的。

他问了两个问题：作为开发者，你在用任何付费插件或 IDE 插件吗？你知道哪些有名的付费插件吗？他还专门 @ 了十位做过 VS Code 插件的人。

周刊在 2021 年 7 月收录了这个帖子，并给出了它的统计：98% 的回答是 No。周刊的原话是，大家用的基本上都是免费的插件，有付费的也非常少。

结论下得很干脆：通过 VS Code 插件实现赚钱的目的并不现实。

这个结果不难理解，但值得看清它是怎么形成的。插件生态的供给方是编辑器自己，编辑器不收插件的钱，插件作者也就很难向用户收钱——用户心里那杆秤从一开始就没有"插件要付费"这一格。这不是某个人定价定错了，是整个类目没有定价的位置。

周刊在给出否定结论之后，转了一个弯：倒是可以多了解一下怎么开发一个 VS Code 插件，这样可以在合适的场景里自己写一个，提高开发效率。

这句话把插件从"商品"移到了"工具"的位置。作为商品，它的价格被生态压到接近零；作为工具，它的价值由使用它的人自己兑现——省下的时间不需要开发票，也不需要经过应用商店。

帖子的回答里，周刊挑出了一个它觉得有意思的例子：一个关于 DeFi 的插件，可以根据区块链地址查看实时的 DeFi 价格和信息。这个插件是开源的，源码可以直接下载下来研究。

这个例子的价值不在 DeFi，在它的形态：一个垂直场景里的信息查询，被做成了一个随手可调用的面板，然后开源。它没有试图卖钱，但它证明了一件事——插件的入口足够轻，轻到可以塞进任何高频动作旁边。

同一件事，从"能不能赚钱"看，答案是 98% 的 No；从"能不能省时间"看，答案是每天都有人在做。两个问题的答案不一样，是因为它们问的根本不是同一件事。

## 可用观点

- 定价权属于生态的供给方：当平台自己免费提供同类能力时，第三方的价格上限不是由成本决定，而是由用户的预期决定
- 插件更适合被当作内部工具而不是商品：它的回报体现在使用者的时间账上，不在收入表上
- 判断一个平台值不值得做，先看这个平台上有没有"付费"这个动作发生过，而不是看用户量
