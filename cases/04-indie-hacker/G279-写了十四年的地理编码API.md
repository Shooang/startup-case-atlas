## 故事正文

欧文·鲁奇做的产品叫 geocode.xyz，一个地理编码和地理分析的 API。2016 年推出，现在每天有数千名用户，每月 API 调用超过 1 亿次，月收入超过 1.5 万美元。这个数字比一年前增长了 1000% 以上，而且当月的数据总是高于前一个月。

想法始于研究生院。那时候他需要地理定位的 API，但市面上几乎没有——谷歌地图还没发布。他没有做任何验证，因为这就是他自己在别的项目里需要的产品。

技术上这件事不轻。地理编码要把 NLP 技术、计算几何算法和快速内存数据库拼在一起。2004 年，他们花大约一个月做出第一个地理编码 API，只支持加拿大，也只做地理编码；后来扩到美国。流程大体是写脚本清洗和导入不同来源的数据，验证、测试，评估各种性能和准确率指标，再微调——性能和准确率之间永远是一个反向的取舍。他前后做了 14 年，至今还不时调整。

2016 年他开始重写今天的 geocode.xyz。时机是因为 OpenStreetMap 和各种政府开放数据项目做成了，全球有足够多的开放地理数据可用，这件事才值得做。重写后的软件用强化学习技术从任意长度的文本里做地理定位和消歧，再和完全基于开放数据的现有地理编码数据集匹配。

启动成本接近于零：域名 1 美元，服务器用的是 AWS 上的免费云实例。两年下来，随着收入增加，经营成本才慢慢上来。他把软件按小时出租，价格在 0.10 美元到 6.00 美元之间，取决于硬件上的 CPU 数量；客户关系由 AWS 处理，这部分业务是自动化的。他也直接卖 API 访问权限，定价页是最近才上线的——此前很长一段时间 API 是免费的，大部分收入走 AWS 市场。相比最接近的竞争对手，他选择了很便宜的 API 定价。

发布大约 6 个月后，产品才被注意到，开始有第一批客户。第一个客户是一名记者，想分析 2016 年前后当地对欧洲移民危机的态度，用 geocode 做了一些实时数据可视化。他花时间为对方调优，但没收钱，所以严格来说不算客户。第一个付费客户出现在 2017 年 12 月。2018 年 1 月多了 3 个，2 月多了 5 个，之后一路往上。2018 年初开始有很多客户，他才敢把这个东西叫"业务"。

他也坦白，自己不知道 2018 年到底发生了什么。2017 年他投入了很多努力，结果很少。他的营销仅限于在会议上演讲，剩下的可能是有人觉得这个 API 好用，就链接过来，或者在论坛上写了正面评价。

运营成本保持在总收入的 10% 以下。他提到，过去 13 年，他每年都比之前 7 年做全职软件开发时更努力，也赚得更多。

## 可用观点

- 技术型产品的壁垒往往不是想法，而是愿意在一件不性感的事上堆 14 年，且期间没有反馈
- 窗口比努力更决定结果：同样的产品放在开放地理数据成熟之前，市场接不住
- 对增长原因保持诚实，比总结出一套方法论更有价值——他明确说 2018 年发生了什么自己也不知道
