## 故事正文

Dirk Hoekstra 在阿姆斯特丹做软件开发，全职。

他业余想做一个新闻文章目录，展示所有被收录的新闻文章的截图。要做这件事，他得先能把网页截下来。他上谷歌搜，找到现成的截图 API，试了一个，能用，但每月要收 35 美元。

他不想付这个钱，于是决定自己写一个。

写着写着他意识到，这东西不只是给自己用的——可以做成一个截图 SaaS。这个转折很小，但方向变了：从"省 35 美元"变成"卖给别人"。

他是全职工作，只能在下班回家后强迫自己挤一两个小时写代码。几个月后，screenshotapi.net 跑起来了。

技术上没什么花活。后端 Laravel，前端 JavaScript 加 Vue，截图的方式是真的启动一个 Chrome 浏览器（用 Selenium）去打开页面。好处是渲染结果和在普通电脑上看到的完全一样，代价是每个截图都要真的跑一次浏览器。

然后他撞上了几乎所有开发者都会撞的那堵墙：产品做出来了，不知道怎么拉用户。

他做的第一件事很朴素——去看竞争对手在干什么。他用 Ahrefs 查对手的流量从哪来、反向链接从哪来，然后照着做。结果不太好：大部分外链并没有带来流量，他的判断是它们对 SEO 有一点价值，但仅此而已。

真正起作用的是谷歌广告。他每月花 100 美元，只投"screenshot API"这个词。到现在，20 个付费用户里有 13 个来自付费广告。

这就是这个产品的全部结构：20 个活跃付费用户，月收入约 400 美元，每月广告支出 100 美元。不是暴利，但它自己养得起自己。

这里有个容易被忽略的细节：那个每月 35 美元的现成 API，其实帮他做了一件事——它证明了"有人愿意为截图付钱"。他不用再去论证市场存不存在，因为账单已经存在了。他要做的只是把价格打下来，然后卖给和他一样不想付 35 美元的人。这是替代品创业最省力的一种开局：需求被对手验证过，你只需要在价格或体验上赢一点。

另一件值得记下的是他试错的方式。他不是先想清楚渠道再做产品，而是产品先跑起来，渠道靠观察对手、靠小额广告一点点试出来。外链那一条他试过、判断无效就放下了；广告那一条他看到数据有效，就停在那里，不追加。这种"小额定投"的试法，代价是每月 100 美元，收益是一条被验证过的获客路径。

他给自己划了一条线：如果截图 API 做到 1000 美元 MRR，他会考虑全职做；在那之前，这就是个副业。他手上还有别的想法，想再做一些简单的小 SaaS。他的判断是，把一件小事解决得极好，胜过把五件大事搞砸。

## 可用观点

- 先自用、再外售是一条风险极低的选题路径：你自己就是第一个用户，35 美元的账单就是需求的第一个证据
- 小工具类产品的分销可以被"买"出来：100 美元/月的精准关键词广告，换回 65% 的付费用户，这是可计算、可复制的获客模型
- 副业产品需要一个明确的止损/转正阈值（这里是 1000 美元 MRR），否则它会在"再优化一点"里无限延长
