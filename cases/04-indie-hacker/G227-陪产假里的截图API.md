## 故事正文

Dmytro Krasun 做服务器端开发约十年，写代码十五年。他有副业项目，也想试试做企业家，但上班时很难发布任何东西——他总把日常工作放在第一位。他说，这可能也正是他成长得快、赚得不少的原因。

机会很偶然。家里有了新宝宝，他休陪产假，觉得这是个好时机：一边带孩子，一边启动一个项目。这是个艰难的决定，最后他还是毫无计划地跳了进去——他说，可能只是自己疯了，这事"感觉"像一场有趣的冒险。

他构建 API 的经验很丰富，坐下来把遇到过的问题一条条写下来，从中挑了一个看起来随机的方向：截图 API，边做边验证。谷歌一搜，他发现已经有很多竞争对手，而且都不错，一开始很失望。后来他想通了：这说明市场已经被验证过，他只需要在这个细分里做出最好的产品。

2022 年 1 月 5 日，他买了域名，搭了个很简单的网站，开始写和产品相关的内容。写法很具体：写下构建产品时遇到的每个问题，以及怎么用自己的产品更快更便宜地解决。比如他的截图 API 可以在渲染截图时隐藏广告和 cookie 横幅，他就先写"如何自己免费做到这一点"，再把产品作为替代方案推荐。

他做仪表盘，让潜在客户试用、看历史、升级套餐、配置通知；界面是 Go 渲染的纯 HTML、CSS 和 JavaScript，他不会用现代 JavaScript 框架。托管从 Digital Ocean 的一台 droplet 起步，增长后换到 Render，再迁到谷歌云。

2022 年 5 月底第一版就绪。因为提前写了内容，他从谷歌拿到一些流量，但不足以带来销售。他又去 Reddit、Indie Hackers、论坛、目录站和 Twitter 写东西，还把第一个营销月做的事总结成帖子发在 Indie Hackers，成了当月最热的帖子。

他几乎放弃，很累。2022 年 7 月 4 日，他迎来了第一位付费客户：推特上的朋友 Jannis 正在做面向创作者的工具目录，需要自动截图。

他说，如果今天重新开始，他不会从 SEO 开始，而是快速做一个带付费链接的原型，拿给潜在用户看。SEO 是长期游戏。

现在月收入两千两百美元。主要流量来自 Twitter 和 Google，推特上一万粉丝，在"screenshot API"这类竞争最激烈的关键词上排进前五。

## 可用观点

- 先写问题再写产品：把"怎么免费做到"写成内容，产品就是那个更省事的替代方案，转化自然发生
- 竞争者是验证报告：一堆不错的对手说明市场成立，剩下的问题只是在细分里做到最好
- 渠道要能反复取用：SEO 见效慢但可复用，他承认如果重来会先用原型换反馈
