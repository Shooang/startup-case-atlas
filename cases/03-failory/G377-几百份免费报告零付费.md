## 故事正文

Gregg Blanchard 在犹他州做市场，职业生涯大多在小团队里，什么都得干，包括设计和写代码。他发现自己的手艺"从很糟变成了没那么糟"，就开始一个接一个做小工具。Readership 是其中之一，和合伙人 Patrick 的另外几个产品摆在一起。

起因是他对 Twitter API 的偏爱。他说那像趴在世界任何一场对话的墙头上偷听。

Readership 从一个实验开始：把推文里的短链接展开，提取域名。他先拿自己的账号试，发现了一些好笑的规律——他是单板滑雪爱好者，收藏里一堆雪相关的链接；他有两个小孩，转发里一堆育儿内容。很快他意识到，同样的分析可以套到任何账号上。

产品做在 Twitter 免费的公开 API 上。存两三万条某公司受众互动过的链接只要几分钟，但都是短链，看不到域名；他得先做一个足够快的链接展开器。这一段比他预计的久得多。报告界面用的是他几年前给自己做的一套 UI 组件，出得很快。

定价很直接：一份报告 99 美元，不带任何品牌，可以转售或白标。他们的假设是——公关公司会买下来转手卖给客户，按他对行业的理解，低端能卖到 250 到 500 美元。

发布前，他找了大约 10 到 15 位公关从业者聊，发样本报告给他们看。上线时，他推给了一个约 2000 人的订阅名单，加上新闻稿、Betalist、Product Hunt 这一套。

结果是这样：几百个人申请免费样本报告，没有一个人升级付费，也没有人要第二份。

他把那些早期对话回忆得很具体。他把样本发过去，对方说："okaaayy, soooo…"——然后他开始解释，如果他是对方，他会拿这份报告做什么。可对方才是专家，他不是。他说，那些反应本该让他当场停下的。

他没停。他喜欢这个产品，而且它"快做完了"。于是继续推，直到发布。

他自己的总结只有一句：Readership 是个很酷的工具，几乎没有现实价值。他本该听早期那些警告，但他被"做这件事有多好玩"和"已经投进去的时间"晃了眼。所有人都说"哇这个很酷……但是……嗯……我到底拿它干什么？"它从来没有解决过一个问题，也从来没有提供过可触摸的价值，只是好看。

他不认为自己早期流程有问题：做原型、找一堆人聊、把产品推到"差不多能用"，这些他都做对了。要改的只有一件事——更认真地听，对自己更诚实一点，承认对方在说什么。

钱的损失只有时间。他一度想用 GNIP 的 API 拿到完整的展开链接，也通过了 Pipl 的审核，可以分析邮件列表而不只是 Twitter 受众，但在认清现实后都搁置了。他估算总共投入 100 多个小时——对一个副业来说，这是很多个晚上和周末。

访谈里他还讲了一个对照。同期他们在做另一个产品 Hemlock，那个是真有人付钱的，但上线几个月流失率高得离谱。Patrick 每次有人退订都去追问，回答高度一致："我很喜欢这个工具，但第一个月我就把它需要给我的东西全拿到了，我不再需要它了。"加什么功能都没用。

## 可用观点

- 用户说"很酷，但是……"的时候，"但是"后面就是产品的死因，不需要再等发布数据
- 白标转售是个假设，不是渠道：如果连专家都说不清拿它做什么，转售链条根本不存在
- 沉没的时间会伪装成"快做完了"，让人把最后一段路走完再撞墙
