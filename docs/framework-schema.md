# 框架卡规范（Framework Cards）

这套卡把书里的**判断工具**取出来，写成能独立使用的条目。它不是读书笔记，不是书摘，也不是书评。

一句话标准：**读一张卡，你应该能拿它去判断一件事；读完这本书，你不一定做得到。**

---

## 一、字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | `F001` 起，全局唯一，不重用 |
| `type` | 是 | 固定写 `framework` |
| `title` | 是 | 中文标题。陈述一个判断，不是概念名。见"标题写法" |
| `title_en` | 是 | 英文标题，8–14 词，陈述句 |
| `hook` | 是 | 一句能直接念出来的开场，25–60 字。见"钩子写法" |
| `book` | 是 | 书名，与封面一致 |
| `author` | 是 | 作者，多作者用顿号 |
| `edition` | 是 | 出版社、版次或年份、ISBN（有则写）。**必须能定位到具体版本** |
| `chapter` | 是 | 章 / 节标题，含编号 |
| `locator` | 是 | 定位方式。电子书无页码写"电子版无页码，正文'某句'起"；纸质书写页码 |
| `quote` | 是 | 原文引句，**不超过 50 字**，见"引文铁律" |
| `doctrine` | 是 | 所属领域，取自词表 |
| `tags` | 是 | 2–5 个，取自失败机制词表（与案例卡共用） |
| `applies_to` | 是 | 3–5 条，这张卡能拿来判断什么，写成动作 |
| `related_cases` | 否 | 现有案例库里的 `Gxxx`，最多 3 个，必须真能对上 |
| `status` | 是 | `未使用`，用过后改成发布期号 |

`doctrine` 词表：`strategy` `management` `pricing` `product` `marketing` `operations` `finance` `organization` `decision` `consumer`

## 二、正文三段

固定三个二级标题，顺序不可变。

### `## 这个框架在说什么`（900–1200 字）

把书里的东西讲清楚，**不评价**。要求：

- 先给一句总判断，再展开。不要从背景讲起
- 保留书里的**原例和原数据**：谁说的、什么公司、什么数字。这是深度的来源
- 有分类的必须列全（四类就写四类，不能只写两类）
- 可以用自己的话解释，但不能加书里没有的观点

### `## 能拿来判断什么`（700–900 字）

这是整张卡的价值所在。要求：

- 3–4 条，每条一个小标题式的粗体开头
- 每条必须落到**一个能执行的动作或判断**，不是"要重视""要思考"
- 能给硬标准的给硬标准（"三个都是是，是延伸；缺两个，是分散"）
- 能接案例的接案例，用 `Gxxx` 引，一句话说清对应关系

### `## 出处与边界`（400–600 字）

**这一段最容易被跳过，也最能说明卡片是否可信。** 要求：

- 交代版本、章节、原文位置
- 至少写 **3 条边界**，且必须包含：
  - 适用条件（什么情况下这个方法不成立）
  - 时代局限（书写于哪年，哪些前提已经变了）
  - 作者立场（当事人自述？事后总结？有商业利益？）
- 明确区分"书里写的"和"我们推的"

**合计正文 2000–2700 汉字。** 低于 1800 字的卡退回重写。

## 三、标题写法

标题陈述一个判断，不是概念名。

- 好：`免费从来不是一种价格，是一种补贴结构`
- 好：`看似什么都能做，其实就是做什么都不知道`
- 差：`免费模式` （概念名，没有判断）
- 差：`关于免费的四点思考`（空壳）

判断从哪里来：优先用书里那句最锋利、最反常识的原话；次优是把书里的论证压缩成一句陈述。

**禁止标题党**：不用感叹号、不用"震惊""颠覆""你绝对不知道"。

---

## 四、钩子写法

`hook` 是给口播用的开场，25–60 字，一句到两句。

三条硬规则：

1. **从读者的经验切入**，不从书切入。不写"德鲁克在书里说……"
2. **留一个悬念或反差**，让听的人想知道答案
3. **不剧透结论**，把最有力的那句留在正文

- 好：`今天早上你用了多少免费的东西？问题不是它们为什么免费，是——谁在替你付钱。`
- 好：`雷军大学创业最惨的时候，派合伙人去跟食堂大师傅打牌，赢饭票。他们到底做错了什么？`
- 差：`今天我们来讲讲安德森的免费理论。`（从书切入，无悬念）

---

## 五、引文铁律

`quote` 是整张卡唯一直接引用原文的地方，规则很硬：

1. **不超过 50 字。** 超过就截断到一句完整的短句
2. **必须来自原生文字层。** OCR 出来的文本有 3–5% 错字率，**不得作为引文来源**；扫描书只做改写，`quote` 留空并写 `quote: ""`，同时把 `locator` 改成描述性定位
3. **一字不改。** 不改标点、不改措辞、不合并句子
4. **不用双引号包裹内容。** front matter 里用双引号界定字符串，内容里的引号用中文引号「」或书名号，否则 YAML 会断

---

## 六、定位规则

电子书没有页码，编页码就是造假。三种写法：

- 纸质书：`第 137 页`
- 电子书：`电子版无页码，第4章"信息挑战"，正文"要学的第一件事是学会谦虚"起`
- 扫描 + OCR：`电子版无页码，第3章，OCR 第 62 页（原书页码不清）`

`locator` 的作用是**让人能回去核对**。只要能做到这一点，格式可以灵活。

---

## 七、关联规则

`related_cases` 只在**真能对上**的时候填，不为了好看硬凑。

判断标准：这个案例里发生的事，用这张卡的逻辑解释，比用其他解释更清楚。

- 能对：`F004 → G623`（59.9 元券 = 直接交叉补贴用错场景，没有刀片可以卖）
- 不能对：`F002 → G663`（战略五必然 ↔ 汤店关停，没有解释力，只是都在讲商业）

宁可不填，不要填错。填错的关联会毁掉两个条目的可信度。

---

## 八、禁止清单

- 不写"这本书告诉我们""值得我们深思"
- 不写读书笔记式的章节摘要（第一章讲了……第二章讲了……）
- 不做人生感悟、价值观输出
- 不把作者的观点当成事实陈述，一律标明"作者认为"
- 不引用书中提到的、但你无法核实的第三方数据（要么标明转引，要么不用）
- 不在卡片里评价作者本人
- 一本 300 页的书最多出 15 张卡。凑数会把一本好书拆成废卡

---

## 九、质检清单

批量产出后逐张过一遍：

- [ ] 正文汉字数 ≥ 1800
- [ ] 三段标题齐全且顺序正确
- [ ] `quote` ≤ 50 字，且非 OCR 来源
- [ ] `locator` 能让人回去核对
- [ ] 边界写了 ≥ 3 条，含适用条件、时代局限、作者立场
- [ ] `hook` 从读者经验切入，无剧透
- [ ] `related_cases` 中的每个 G 编号都真实存在
- [ ] 没有"这告诉我们""值得深思"这类空话
- [ ] `id` 不与已有卡重复

---

## 十、黄金样例

`F004-免费不是一种价格而是一种补贴结构.md`（2068 字）

看的时候注意四点：它把四种模式全列了；每条判断都给了一个能执行的动作；边界写了四条，包括作者的自我修正和"实体生意不适用"；最后用一句反问收尾，没有升华。
